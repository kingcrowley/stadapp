# Slice 2.2 — Escape log — Design

**Date:** 2026-11-21
**Branch:** `phase/2-slice2-escape-log` (cut from `phase/2-slice1-lock-survives`; rebased onto `main` once 1.3 and 2.1 merge)
**Status:** draft, before independent review

## Why this replaces "Close the escape routes"

The roadmap's 2.2 planned to block uninstalling Stad, turning off its Accessibility service, and reaching its App info screen while locked. Google Play forbids all three for an app like Stad:

- **Accessibility API** (Play Console Help, "Permissions and APIs that Access Sensitive Information"): it "cannot be used to: Change user settings without their permission or prevent the ability for users to disable or uninstall any app or service, unless authorized by a parent or guardian through a parental control app or by authorized administrators through enterprise management software". Stad is neither.
- **Malware policy**, ransomware: "Leveraging device policy manager features and blocking removal by the user"; "Don't use device admin features to block uninstallation."
- **Malware policy**, elevated privilege abuse: "Apps that abuse features to prevent them from being uninstalled or stopped."

Doing it anyway risks Play rejecting Stad or terminating the developer account. So in the Play build, Stad stays easy to turn off and remove. What it can do is make turning it off while locked **visible**: an honest record you see the next time you open Stad. A strict F-Droid-only build that closes the routes is a possible later slice (`TODO(slice2.x-strict-fdroid)`), outside Play's rules but not outside Android's (safe mode still beats it).

## Goals

1. When blocking stops while Stad is locked (Accessibility service turned off, Stad force-stopped, blocking otherwise not running), Stad records when it stopped and when it came back.
2. Home shows the record: the latest few times "Blocking was off while locked: 14:02 – 14:20 (18 min)", and how many times in the last 7 days.
3. The record is plain and non-judgemental, stays on the phone, and can be cleared only while unlocked.
4. Nothing in the Play build prevents disabling, stopping or uninstalling Stad.

## Non-goals

- Blocking uninstall, the Accessibility switch, App info or Force stop (Play policy; see above).
- Recording uninstalls (the record goes with the app) or safe-mode boots (no app code runs). `TODO(slice2.x-safe-mode-gap)` if a reliable signal appears.
- Sharing the record or any network use.

## Behaviour

### What counts as an "off period"

An off period starts when blocking stops working while locked and ends when it works again or the lock is removed. Detected from three places, all writing through one pure decision in core:

| Moment | Where | Recorded |
|--------|-------|----------|
| Service unbound or destroyed while locked (user turned it off; system disabled it), not during shutdown | `BlockerAccessibilityService.onUnbind` / `onDestroy` | `off_since = now` |
| Stad finds it's locked, the service is off, and no `off_since` is set (force-stop: no code ran when it stopped) | Home `onStart`, `BootReceiver`, tag tap | `off_since = last_alive` (approximate, shown as "about") |
| Service connects while locked with `off_since` set | `onServiceConnected` | entry `(off_since, now)`; clear `off_since` |
| Unlocked with `off_since` set (tag tap while the service was off) | Tag tap / lock change | entry `(off_since, now, endedBy = Unlock)`; clear |

`last_alive`: the service writes it when it connects and at most every 15 minutes on window events while locked. Event-driven only: no timers, no wake-ups, no battery cost while the screen is off.

A reboot is not an off period. Shutdown may unbind or destroy the service, which would look like the user turning it off, so:

- `BootReceiver` also listens for `ACTION_SHUTDOWN` (on the implicit-broadcast exception list, so a manifest receiver gets it) and stores `shutdown_at = now`. A service stop within 60 s of `shutdown_at` doesn't set `off_since`.
- Fallback when that broadcast is missed (a crash or battery pull): on `BOOT_COMPLETED`, an `off_since` that was set by a service stop within 2 minutes before this boot started (`now - elapsedRealtime`) is cleared.

Off periods shorter than 30 seconds are dropped (service restarts after an update or crash).

### Home

Under the service card, when the log has entries in the last 7 days:

> **While locked, blocking was off 2 times this week.**
> Today 14:02 – 14:20 (18 min)
> Tuesday about 09:10 – 09:45 (35 min, after Stad was force-stopped)

Up to 5 entries; a "Clear" button only while unlocked. The block list rule still holds: nothing about blocking changes while locked, and clearing the record counts.

### Data

`EscapeLog`: up to 50 entries `{start, end, startApprox, endedBy: ServiceBack | Unlock}`, oldest dropped. Stored in the shared DataStore as one string (`escape_log`), with `off_since` and `last_alive` as longs. Wall-clock times (`System.currentTimeMillis`), since the record must survive reboots; a clock change can make an entry look odd, which is acceptable for a personal record.

Pure core:
- `EscapeTracker.onServiceStopped / onServiceConnected / onFoundOff / onUnlocked / onShutdown / onBoot(state, now, bootStartedAt) -> new state + optional entry`
- `EscapeLog.add / recent(now, days) / encode / decode` (decode tolerant: a corrupt value reads as empty)
- `EscapeLog.summary` for Home text.

## Play policy

No new permissions. `06_PLAY_POLICY.md` gains a row: "Stad never prevents disabling, stopping or uninstalling itself; while locked it only records when blocking was off, on the device". The prominent disclosure gains one sentence: "If you turn this off while locked, Stad notes when, so you can see it later."

## Acceptance

- CI green. JVM tests for `EscapeTracker` (each transition; force-stop uses `last_alive`; unlock ends a period; short periods dropped; reboot not recorded) and `EscapeLog` (cap, recent window, encode/decode round-trip, corrupt input).
- On the phone, locked with Instagram blocked:
  1. Turn the service off in settings, wait, turn it on → Home: "blocking was off" with the right times.
  2. Force-stop Stad, wait, open Stad, turn on → entry marked "about", starting no later than the last time blocking was seen working.
  3. Reboot → no entry.
  4. Unlocked: turning the service off records nothing.
  5. Clear is hidden while locked and works while unlocked.
