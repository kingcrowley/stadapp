# Slice 1.1 — Block list — Design

**Date:** 2026-11-17
**Branch:** `phase/1-slice1-block-list`
**Status:** planned

## Problem

Stad can't block anything until it knows *what* to block. This slice lets the user choose apps from the ones installed on the phone, and keeps that choice across restarts. Nothing is blocked yet: that is slice 1.2.

## Goals

1. A searchable app picker listing the phone's launchable apps (icon, name, checkbox).
2. The selection persists on the device and survives killing and reopening Stad.
3. Apps that must never be blocked (Stad, the launcher, the Phone app, Settings) can't be selected.
4. The home screen shows how many apps are blocked and opens the picker.
5. The "read-only while locked" rule exists in `core/` with tests, ready for 1.2 to switch on.

## Non-goals

- Blocking, the Accessibility service, the block screen (1.2).
- Persisting the lock state (2.1). In 1.1 the lock is always `Unlocked` in memory.
- Categories, schedules, multiple block lists or profiles.
- Work-profile apps (the picker shows the main profile only). `TODO(slice1.1-work-profile)`.

## User flow

1. Home: "Unlocked · 0 apps blocked" and a **Choose apps** button.
2. Picker: search box on top; list sorted A–Z by app name; ticking or unticking saves at once (no Save button). Protected apps appear greyed out with "Can't be blocked" so it's clear why.
3. Back to home: "Unlocked · 3 apps blocked".
4. While locked (from 1.2 on), the picker opens read-only with a banner "Unlock with your tag to change this list."

## Design

### core/ (pure Kotlin, JVM-tested)

| Type | Responsibility |
|------|----------------|
| `AppEntry(packageName, label)` | One launchable app, as the picker sees it |
| `BlockList` (value class over `Set<String>`) | `contains`, `size`, `toggled(pkg)` |
| `BlockListRules` | `canEdit(lockState)`; `isBlockable(pkg, protected)`; `toggle(list, pkg, lockState, protected)` returns the list unchanged when locked or protected; `sanitize(saved, installed, protected)` drops uninstalled and protected packages; `pickerRows(apps, list, protected, query)` filters by query (case- and accent-insensitive, matches name or package), sorts by name, and marks each row checked / disabled |

### data/

- `BlockListRepository` interface: `val blockList: Flow<BlockList>`, `suspend fun setBlocked(pkg, blocked)`, `suspend fun replace(list)`.
- `DataStoreBlockListRepository`: Preferences DataStore file `stad_settings`, key `blocked_packages` (string set). Corrupt file → empty list (`ReplaceFileCorruptionHandler`), never a crash.

### service/ (Android, thin)

- `InstalledApps`: `PackageManager.queryIntentActivities(ACTION_MAIN + CATEGORY_LAUNCHER)` → `List<AppEntry>`, run on `Dispatchers.IO`. Icons loaded lazily per row, not up front.
- `ProtectedPackages`: Stad's own package; the default home app (`ACTION_MAIN` + `CATEGORY_HOME` resolve); the default dialer (`TelecomManager.defaultDialerPackage`); the Settings app (`Settings.ACTION_SETTINGS` resolve). Computed when the picker opens, so changing the default launcher is picked up.
- Manifest: a `<queries>` element for the launcher intent. **No `QUERY_ALL_PACKAGES`** (Play-restricted, see `06_PLAY_POLICY.md`).

### ui/

- `BlockListViewModel` combines the stored list, installed apps, protected packages, lock state and search query into `UiState(rows, blockedCount, editable, loading)`.
- On first load it calls `sanitize` and writes back if anything was dropped (e.g. an uninstalled app), so the count on Home stays honest.
- Screens: `HomeScreen` (count + Choose apps), `AppPickerScreen` (search + `LazyColumn`).
- Navigation: two screens, so a simple screen state in `MainActivity` with `BackHandler`. Move to navigation-compose when a third screen arrives (1.3, pair tag). `TODO(slice1.3-navigation)`.

### New dependencies

| Library | Why |
|---------|-----|
| `androidx.datastore:datastore-preferences` | Persist the list (agreed in the architecture doc) |
| `androidx.lifecycle:lifecycle-viewmodel-compose` | `viewModel()` in Compose |
| `org.jetbrains.kotlinx:kotlinx-coroutines-test` (test) | Repository and ViewModel-free flow tests |

All three are Google/JetBrains open-source, no Play Services, so F-Droid is unaffected.

## Edge cases

- **App uninstalled after being picked:** dropped by `sanitize` next time the picker or Home loads.
- **Default launcher changes to a picked app:** it becomes protected; `sanitize` drops it.
- **App with no label / duplicate labels:** fall back to package name; sort ties broken by package name.
- **Hundreds of apps:** list is lazy; icons load per visible row.

## Play policy

The block list is the user's own setting, stored only on the device. Listing apps uses a `<queries>` launcher intent, not `QUERY_ALL_PACKAGES`. No new permissions. `06_PLAY_POLICY.md` already covers this; the slice ticks it off.

## Acceptance

- CI green: build, unit tests, lint.
- ~20 new JVM tests (`BlockListRules`, `BlockList`, `DataStoreBlockListRepository` on a temp file).
- On David's phone: pick 3 apps → Home says 3 → swipe Stad away, reopen → still 3 and the same apps ticked. Search finds an app by part of its name. Phone, Settings, the launcher and Stad show as "Can't be blocked". Uninstall a picked app → count drops by one.
